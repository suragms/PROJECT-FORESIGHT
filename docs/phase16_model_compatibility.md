Features are generated by `src/feature_engineering.py`. Key features and their dataset compatibility:

| Feature Category | Features | Source | Leakage Risk | UCI Compatible | Synthetic Compatible |
|-----------------|----------|--------|--------------|----------------|---------------------|
| Temporal | day_of_week, month, quarter, week_of_year, year | Calendar math | None | Yes | Yes |

## 6. Risk Scoring Compatibility (Section 22)

### Current Implementation (`src/risk_scoring.py`)

| Zidio Requirement | Implementation | Status |
|-------------------|---------------|--------|
| Forecast demand for stockout | Uses `avg_daily_demand` from last 30 days of **historical** actuals | **RISK LOGIC GAP IDENTIFIED** |
| Lead-time demand | `effective_daily_demand × lead_time_days` | PASS |
| On-hand inventory | `ending_inventory` from latest snapshot | PASS |
| On-order inventory | `on_order_qty` from latest snapshot | PASS |
| Safety level | `safety_stock` from sku_master | PASS |
| Overstock: on-hand vs forward demand | Uses historical `avg_daily_demand`, not forecast | **RISK LOGIC GAP IDENTIFIED** |
| Overstock: forecast horizon consideration | Uses `target_coverage_days=45` (configurable) | PARTIAL |

### Risk Logic Gap

**RISK LOGIC GAP IDENTIFIED**: The current `src/risk_scoring.py` calculates `avg_daily_demand` from the last 30 days of historical sales data (line 46–52), NOT from the frozen forecasting models. The Zidio specification requires forecast-based demand for risk scoring.

**Recommendation:** Do NOT silently change risk scoring in Phase 16. Implement forecast-driven risk scoring in a future controlled phase (Phase 17+) after proper validation.

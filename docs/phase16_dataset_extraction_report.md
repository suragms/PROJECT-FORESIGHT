### UCI Inventory Rule (MANDATORY)

The UCI Online Retail II dataset does **NOT** provide:

- on-hand inventory → `NOT AVAILABLE FROM SOURCE`
- on-order inventory → `NOT AVAILABLE FROM SOURCE`
- lead time → `NOT AVAILABLE FROM SOURCE`
- reorder point → `NOT AVAILABLE FROM SOURCE`

### UCI Revenue

Revenue = `Quantity × Price` (derived). The `Price` column represents unit price. Returns are identified by negative quantities; cancellations by invoice prefix "C".

## 4. Current Repository Synthetic Data — Provenance

**CURRENT SYNTHETIC DATA = REPOSITORY-GENERATED SYNTHETIC DATA**

The current synthetic dataset was generated by `src/generate_synthetic_retail.py`, which uses `numpy.random.seed(42)` to produce:

| Table | Rows | Key Identifiers |
|-------|------|-----------------|
| store_master.csv | 30 stores | STORE_001 to STORE_030 |
| sku_master.csv | 5,000 SKUs | SKU_00001 to SKU_05000 |
| customer_master.csv | 10,000 customers | CUST_000001 to CUST_010000 |
| calendar.csv | 1,461 days | 2022-01-01 to 2025-12-31 |
| sales_daily.parquet | 1,461,000 rows | 10 stores × 100 SKUs × 1,461 days |
| inventory_snapshots.parquet | 1,461,000 rows | 10 stores × 100 SKUs × 1,461 days |

**Important observation:** The generator defines 30 stores and 5,000 SKUs in master tables, but `sales_daily` and `inventory_snapshots` only use 10 stores × 100 SKUs. This is a deliberate design choice in the generator.

**KAGGLE EQUIVALENCE = NOT PROVEN**

The Kaggle dataset describes "10 Million Transactions" — the repository has 1,461,000 sales rows. The scale alone strongly suggests these are **different datasets**.
